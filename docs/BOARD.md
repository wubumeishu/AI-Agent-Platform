# 项目看板工作规则

## 1. 看板目标

看板不是简单的任务清单。

看板负责记录：

* 当前正在做什么
* 什么已经完成
* 什么正在等待
* 什么需要验证
* 什么暂时禁止开发

---

# 2. 看板状态

统一使用：

BACKLOG
↓
READY
↓
IN PROGRESS
↓
REVIEW
↓
QA
↓
DONE

异常状态：

BLOCKED

---

# 3. 状态定义

## BACKLOG

想做，但尚未排期。

不能主动执行。

---

## READY

需求已经明确，可以开始开发。

---

## IN PROGRESS

当前正在开发。

一个开发 Agent 同时只允许处理有限数量的任务。

不得在当前任务没有完成的情况下随意跳到其他任务。

---

## REVIEW

代码已经完成，需要检查：

* 是否符合架构
* 是否重复
* 是否破坏已有功能
* 是否符合项目规则

---

## QA

进入真实运行验证。

必须实际启动软件并验证用户路径。

---

## DONE

只有验收通过才能进入。

---

## BLOCKED

被依赖、环境或外部条件阻塞。

必须记录：

* 阻塞原因
* 阻塞对象
* 下一步处理方式

---

# 4. 任务卡标准

每一张任务卡必须包含：

标题

目标

背景

范围

不包含内容

依赖

实现要求

验收标准

测试方法

完成条件

---

# 5. 任务优先级

P0：

必须完成。

P1：

核心产品功能。

P2：

增强功能。

P3：

以后处理。

---

# 6. 一张任务卡只允许有一个核心目标

错误：

“完成 Agent、CRM、AI、工作流和数据库。”

正确：

“完成 Agent 创建页面与基础数据模型。”

---

# 7. 开发规则

开始任务前：

1. 读取 PROJECT.md
2. 阅读相关架构文档
3. 查看当前代码
4. 查看相关看板卡
5. 检查依赖任务
6. 再开始修改

禁止：

* 根据想象修改代码
* 重写整个项目
* 顺便修改无关模块
* 自行扩大任务范围

---

# 8. 完成规则

开发完成后必须：

1. Build
2. 启动
3. 实际操作
4. 检查日志
5. 检查页面
6. 执行相关测试
7. 更新任务卡
8. 更新相关文档

然后才能进入 QA。

---

# 9. 看板纪律

看板必须反映真实状态。

禁止：

“代码完成”直接标记 DONE。

必须经过：

开发
→ Review
→ QA
→ 验收
→ Done

---

# 10. 用户验收优先

涉及 UI / 用户流程的任务：

代码正确不是最终标准。

最终标准：

> 用户实际打开软件后，功能是否符合需求。
